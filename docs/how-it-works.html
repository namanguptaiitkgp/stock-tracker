stock-tracker

A personal, AI-assisted trading & research platform for Indian equities — built on Zerodha Kite Connect, with a two-tier AI layer and a three-stream “smart-money” signal engine.

FastAPI · Python 3.12 Next.js 16 · React 19 TimescaleDB Celery + Redis Gemini AI

Each box is a running service. The frontend talks only to the FastAPI backend; the backend fans out to the database, cache, broker APIs and AI providers. Long-running work is handed to Celery via Redis.

How the data flows

  1. You open a page. The Next.js frontend calls the backend with your JWT attached.
  2. FastAPI validates the token, then reads through portfolio_cache so concurrent dashboard widgets share one fan-out to Kite.
  3. Market data comes from Kite Connect; fundamentals, news and FII/DII flows come from cached scrapers.
  4. Results are read/written to TimescaleDB and hot values cached in Redis.
  5. The response returns to the browser — no direct DB or broker access from the client.
  1. Celery beat fires run_daily_analysis at 08:30 IST.
  2. The worker pulls every active watchlist symbol.
  3. Gemini Flash-Lite screens each symbol — price action + fundamentals + latest news + smart-money snapshot — and assigns an interest score (cheap, high-volume tier).
  4. A curated shortlist is routed to the deep-analysis provider for a full write-up.
  5. Decisions land in the DB and surface on the “Today” morning brief — news, FII/DII, MF activity, portfolio and recommendations.

The smart-money subsystem scores both new candidates and existing holdings on three independent streams, then derives a composite.

Conviction

Who's buying with intent

Promoter purchases, insider buys, and institutional accumulation — filtered to exclude intra-group transfers that would otherwise score as both buy and sell.

Flow

Where the money moves

Bulk/block deals, FII/DII activity, mutual-fund buy/sell, and shareholding-pattern shifts across configurable windows.

Red flag

What to watch out for

Promoter selling, pledge changes, and governance signals. Coverage gating returns NO_SIGNAL rather than a misleading direction when data is sparse.

Ingestion of each third-party disclosure is audited and validated per run; client names are normalized once so named-investor linkage stays consistent.

  1. Bulk screen runs on Gemini 2.5 Flash-Lite — cheap enough to score every watchlist symbol daily.
  2. Deep analysis goes through a provider-agnostic registry (app/ai/registry.py): call sites ask for a provider by purpose, never a vendor SDK.
  3. Gemini Vertex is the default deep provider; Anthropic and OpenAI classes are scaffolded and switchable per-user in Settings.
  4. Spend is bounded by a per-user daily budget cap, and paid calls require explicit user intent in the UI.
  5. All provider credentials are stored Fernet-encrypted at rest.

Safety rails

Risk engine

Order placement is guarded by position-size, exposure, daily-loss and order-count limits, with a hard kill switch.

Cost caps

Bulk work runs on the cheap model; deep-analysis spend is bounded by a per-user daily budget.

Encryption at rest

Kite, Gemini, Anthropic and OpenAI credentials are stored Fernet-encrypted, never in plaintext.
